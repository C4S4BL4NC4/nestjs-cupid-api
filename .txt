## 📚 **Authentication Architecture - Industry Standards**

### **Lesson 1: Understanding JWT-Based Authentication Flow**

Here's what happens in a modern, secure authentication system:

```
1. REGISTRATION
   User → POST /auth/register → Validate → Hash Password → Save to DB → Return Success

2. LOGIN
   User → POST /auth/login → Validate Credentials → Generate JWT Tokens → Return Tokens + User Data

3. AUTHENTICATED REQUESTS
   User → Request with JWT → Validate Token → Extract User ID → Allow Access

4. TOKEN REFRESH
   User → POST /auth/refresh → Validate Refresh Token → Issue New Access Token
```

#### **B. JWT Strategy**
This tells Passport HOW to validate JWT tokens.

**Example: `jwt.strategy.ts`**
```typescript
import { Injectable, UnauthorizedException } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';
import { ConfigService } from '@nestjs/config';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy, 'jwt') {
  constructor(private configService: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: configService.get<string>('JWT_SECRET'),
    });
  }

  async validate(payload: any) {
    // This payload is the decoded JWT
    // Return the user object that will be attached to request
    return { 
      userId: payload.sub, 
      email: payload.email,
      username: payload.username 
    };
  }
}
```

**What's happening here?**
- Extracts JWT from `Authorization: Bearer <token>` header
- Verifies signature using `JWT_SECRET`
- Decodes payload and calls `validate()`
- Attaches returned object to `request.user`

**Example: Token Generation**
```typescript
async generateTokens(user: Profile) {
  const payload = { 
    sub: user.id,      // 'sub' is JWT standard for user ID
    email: user.email,
    username: user.username 
  };

  return {
    accessToken: this.jwtService.sign(payload, {
      secret: this.configService.get('JWT_SECRET'),
      expiresIn: '15m',  // Short-lived for security
    }),
    refreshToken: this.jwtService.sign(payload, {
      secret: this.configService.get('JWT_REFRESH_SECRET'),
      expiresIn: '7d',   // Longer-lived
    }),
  };
}
```

## 🎯 **Industry Best Practices You MUST Follow**

### **1. Password Security**
- ✅ Hash with bcrypt (10+ rounds) - you're already doing this!
- ✅ Never return password in API responses
- ✅ Use `select: false` on password field (you have this!)
- ❌ Don't store plaintext passwords
- ❌ Don't send passwords in GET requests

### **2. JWT Security**
- ✅ Use short expiration for access tokens (15-30 min)
- ✅ Use longer expiration for refresh tokens (7-30 days)
- ✅ Store tokens in httpOnly cookies (web) or secure storage (mobile)
- ✅ Use different secrets for access/refresh tokens
- ❌ Don't store sensitive data in JWT payload (it's readable!)
- ❌ Don't use localStorage for tokens (XSS vulnerable)

### **3. Refresh Token Strategy**
Options:
1. **Basic**: Just issue new access token (simpler)
2. **Rotation**: Issue new refresh token each time (more secure)
3. **Family**: Track token families, detect reuse (enterprise-level)

For your dating app, **token rotation** is recommended.

### **4. Error Handling**
```typescript
// ❌ Bad: Reveals too much
throw new UnauthorizedException('Password incorrect');

// ✅ Good: Generic message
throw new UnauthorizedException('Invalid credentials');
```

Don't reveal whether email or password was wrong - prevents user enumeration.

## 🏛️ **Industry Standard: Two-Module Architecture**

### **Profiles Module** 
**Purpose:** Manage user profile data
- Should handle: name, bio, age, photos, preferences, interests
- Should NOT handle: passwords, login, tokens

### **Auth Module**
**Purpose:** Handle authentication & authorization
- Should handle: registration, login, logout, token management
- Should NOT handle: profile updates, bio, photos

## 📐 **How to Refactor (Recommended Approach)**

You have **two options**:

### **Option 1: Auth Delegates to Profiles (Recommended)**

```
Auth Module                    Profiles Module
-----------                    ---------------
register() ─────calls────→    createProfile()
login()                        findByEmail()
validateUser()                 comparePassword()
generateTokens()              
```

**Flow:**
1. User hits `POST /auth/register` with credentials
2. `AuthService.register()` validates and creates JWT
3. `AuthService` calls `ProfilesService.createProfile()` to save user
4. Returns tokens + user data

**Benefits:**
- ✅ Clear separation of concerns
- ✅ Auth module owns authentication logic
- ✅ Profiles module is reusable
- ✅ Easy to add OAuth later (Google, Facebook)

Keep `POST /profiles` for now, but add auth-specific endpoints:

- Move registration from `/profiles` to `/auth/register`

### **5. Inject ProfilesService in AuthService**
```typescript
// auth.service.ts
@Injectable()
export class AuthService {
  constructor(
    private profilesService: ProfilesService,
    private jwtService: JwtService,
    private configService: ConfigService,
  ) {}

  async login(loginDto: LoginDto) {
    // Validate user
    const user = await this.validateUser(loginDto.email, loginDto.password);
    
    if (!user) {
      throw new UnauthorizedException('Invalid credentials');
    }

    // Generate tokens
    const tokens = await this.generateTokens(user);
    
    return {
      ...tokens,
      user: {
        id: user.id,
        username: user.username,
        email: user.email,
      }
    };
  }

  private async validateUser(email: string, password: string) {
    const user = await this.profilesService.findByEmail(email);
    
    if (!user) {
      return null;
    }

    const isPasswordValid = await user.comparePassword(password);
    
    if (!isPasswordValid) {
      return null;
    }

    return user;
  }

  private async generateTokens(user: Profile) {
    const payload = { 
      sub: user.id, 
      email: user.email,
      username: user.username 
    };

    return {
      accessToken: this.jwtService.sign(payload, {
        secret: this.configService.get('JWT_SECRET'),
        expiresIn: '15m',
      }),
      refreshToken: this.jwtService.sign(payload, {
        secret: this.configService.get('JWT_REFRESH_SECRET'),
        expiresIn: '7d',
      }),
    };
  }
}
```

### **2. JWT Security**

// auth.service.ts
@Injectable()
export class AuthService {
  constructor(
    private profilesService: ProfilesService,
    private jwtService: JwtService,
    private configService: ConfigService,
  ) {}

  async login(loginDto: LoginDto) {
    // Validate user
    const user = await this.validateUser(loginDto.email, loginDto.password);
    
    if (!user) {
      throw new UnauthorizedException('Invalid credentials');
    }

    // Generate tokens
    const tokens = await this.generateTokens(user);
    
    return {
      ...tokens,
      user: {
        id: user.id,
        username: user.username,
        email: user.email,
      }
    };
  }

  private async validateUser(email: string, password: string) {
    const user = await this.profilesService.findByEmail(email);
    
    if (!user) {
      return null;
    }

    const isPasswordValid = await user.comparePassword(password);
    
    if (!isPasswordValid) {
      return null;
    }

    return user;
  }

  private async generateTokens(user: Profile) {
    const payload = { 
      sub: user.id, 
      email: user.email,
      username: user.username 
    };

    return {
      accessToken: this.jwtService.sign(payload, {
        secret: this.configService.get('JWT_SECRET'),
        expiresIn: '15m',
      }),
      refreshToken: this.jwtService.sign(payload, {
        secret: this.configService.get('JWT_REFRESH_SECRET'),
        expiresIn: '7d',
      }),
    };
  }
}
